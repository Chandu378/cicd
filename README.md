🚀 CI/CD Pipeline Using GitHub Actions

 📌 Project Overview

This project demonstrates the implementation of a Continuous Integration and Continuous Deployment (CI/CD) workflow using GitHub Actions and a Node.js application built with Express.js.

The main objective is to automate the software development workflow by integrating version control, application testing, and CI/CD automation.

Whenever code changes are pushed to the GitHub repository or a workflow is triggered, GitHub Actions can execute the configured automation tasks.

🎯 Project Objectives

- Understand CI/CD concepts and implementation.
- Automate application testing using GitHub Actions.
- Integrate GitHub with a Node.js application.
- Use Jest and Supertest for application testing.
- Understand automated software development workflows.
- Improve application delivery through workflow automation.

💻 Getting Started
1. Project Creation

Step 1: Create a project directory

Open your terminal and execute:

mkdir cicd
cd cicd

Step 2: Initialize the Node.js project

npm init -y

This creates a package.json file containing project information, dependencies, and scripts.

Step 3: Install dependencies

Install Express.js:

npm install express

Install Jest and Supertest as development dependencies:

npm install --save-dev jest supertest

Purpose:

Express.js: Creates the backend application.

Jest: Executes automated test cases.

Supertest: Sends HTTP requests to the application during testing.

2. Application Development

Step 1: Create server.js

Create a file named server.js.

Add the following code:

const express = require('express');

const app = express();

app.get('/', (req, res) => {
    res.send('CI/CD Pipeline Running');
});

if (require.main === module) {
    const PORT = 5000;

    app.listen(PORT, () => {
        console.log(`Server running on port ${PORT}`);
    });
}

module.exports = app;

Explanation

require('express'): Imports the Express framework.

express(): Creates an Express application.

app.get('/'): Defines a GET endpoint.

res.send(): Sends a response to the client.

app.listen(): Starts the application on port 5000.

module.exports: Makes the application available for automated testing.

The require.main condition ensures that the server starts when you execute node server.js, but does not start another listening server when Jest imports the application.

3. Configure Package Scripts

Open package.json and configure the scripts section:

"scripts": {
    "start": "node server.js",
    "test": "jest --runInBand"
}

The start command runs the application.

The test command executes the Jest test suite.

Keep the dependencies and other fields generated by npm.

4. Execute the Application

Run the application:

npm start

Expected terminal output:

Server running on port 5000

Open your browser and visit:

http://localhost:5000

Expected response:

CI/CD Pipeline Running

You can also test the endpoint using curl:

curl http://localhost:5000

5. Create Automated Test Cases

Create a folder named tests.

Inside it, create server.test.js.

const request = require('supertest');
const app = require('../server');

describe('CI/CD Application Tests', () => {

    test('GET / should return successful response', async () => {

        const response = await request(app).get('/');

        expect(response.statusCode).toBe(200);

        expect(response.text).toBe('CI/CD Pipeline Running');

    });

});

Explanation

supertest: Sends HTTP requests to the Express application.

describe(): Groups related test cases.

test(): Defines an individual test case.

request(app).get('/'): Sends a GET request.

expect(): Checks whether the actual result matches the expected result.

toBe(200): Verifies the HTTP success status code.

Execute the test cases:

npm test

Expected result:

PASS tests/server.test.js

Test Suites: 1 passed
Tests:       1 passed

6. Configure GitHub Actions

GitHub Actions automates the testing process whenever code changes are pushed to the repository.

Step 1: Create workflow directories

From the project root:

mkdir -p .github/workflows

Step 2: Create a workflow file

Create:

.github/workflows/nodejs.yml

Add the following YAML configuration:

name: Node.js CI Pipeline

on:
  push:
    branches:
      - main

  pull_request:
    branches:
      - main

jobs:
  build-and-test:

    runs-on: ubuntu-latest

    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 22

      - name: Install Dependencies
        run: npm ci

      - name: Run Automated Tests
        run: npm test

Understanding the workflow

Workflow steps:

Explanation

name

Defines the workflow name

on

Specifies when the workflow should run

push

Triggers the workflow when code is pushed

pull_request

Triggers the workflow when a pull request is created or updated

runs-on

Specifies the GitHub-hosted runner

checkout

Downloads the repository code into the runner

setup-node

Configures the Node.js environment

npm ci

Installs dependencies from package-lock.json

npm test

Executes automated tests

Important: npm ci requires a committed package-lock.json, which is generated when you install dependencies using npm.

 4. Run the Application

node server.js

The application starts on port 5000.

Open your browser and visit:

http://localhost:5000

 🔄 CI/CD Workflow

The project includes a GitHub Actions workflow directory for automating development tasks.

A typical CI workflow follows these stages:

1. Developer pushes code to GitHub.
2. GitHub Actions triggers the configured workflow.
3. Node.js dependencies are installed.
4. Automated tests are executed.
5. Workflow results are reported on GitHub.

Note: The exact triggers and workflow steps depend on the YAML configuration in `.github/workflows/`.
